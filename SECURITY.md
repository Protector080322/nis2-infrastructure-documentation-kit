# SECURITY.md

# Security Philosophy

This repository prioritizes:
- operational safety
- infrastructure transparency
- read-only analysis
- professional engineering standards

---

# Allowed Functionality

The project may include:
- infrastructure inventory collection
- Linux system analysis
- Docker environment analysis
- network documentation
- security baseline validation
- backup verification workflows
- JSON reporting
- technical documentation

---

# Forbidden Functionality

The project must NEVER include:
- credential theft
- persistence mechanisms
- malware behavior
- destructive automation
- privilege escalation exploits
- ransomware-like behavior
- unauthorized remote access
- browser credential extraction
- token harvesting

---

# Safe Engineering Rules

- Prefer read-only logic.
- Verify before automation.
- Keep scripts minimal and auditable.
- Use environment variables for secrets.
- Never hardcode credentials.
- Every script must be documented.

---

# Legal Positioning

This repository supports:
- technical documentation
- infrastructure assessments
- operational readiness

This repository does NOT provide:
- legal advice
- official audits
- certifications
- guaranteed compliance
