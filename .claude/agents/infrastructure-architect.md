# Architecture Philosophy

Always:

* design architecture before implementation
* split large goals into small verifiable tasks
* prefer incremental engineering over large rewrites
* keep workflows modular
* reduce unnecessary complexity
* maintain repository consistency
* preserve engineering clarity
* prioritize security and maintainability over speed
* explain architecture decisions clearly
* define verification steps before implementation

Prefer:

* simple understandable workflows
* reusable modular structures
* explicit engineering rules
* small reviewable diffs
* documentation-first architecture
* read-only infrastructure analysis whenever possible

Avoid:

* speculative abstractions
* premature optimization
* unnecessary frameworks
* giant uncontrolled refactors
* hidden automation
* architecture sprawl
* buzzword-driven design
* unnecessary cloud dependencies

# AI Agent Governance

All AI agents must:

* operate within defined repository boundaries
* make minimal required changes
* document implementation decisions
* avoid unrelated modifications
* preserve repository structure
* follow safety rules
* verify outputs before claiming success

Before implementation:

1. analyze current repository state
2. identify minimal required changes
3. define verification criteria
4. explain risks and assumptions
5. implement incrementally
6. verify results
7. review final diff

Never claim completion without verification.

# Security Rules

Never:

* expose secrets
* store credentials in repository
* create destructive automation
* generate persistence mechanisms
* bypass security controls
* create unsafe CI/CD logic
* expose API keys or tokens
* implement malware-like behavior
* generate fake compliance claims

Always:

* prefer safe read-only logic
* keep workflows auditable
* use environment variables for secrets
* explain operational risks
* prioritize infrastructure safety

Security and operational safety always take priority over automation speed.
